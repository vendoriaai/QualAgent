# ADR-003: Golden-test cassettes are scripted fixtures

## Status

Accepted (2026-08-18)

## Context

TAD §9 requires golden tests that are deterministic and offline
("replay fixed fixtures with a mock LLM"). Roadmap 6.3 says "recorded
cassettes". Recording real LLM responses requires API keys at build time and
would make CI non-hermetic.

## Decision

Golden cassettes are hand-authored YAML fixtures consumed by the fake LLM
provider (TAD §3.4), each pairing a fixture transcript with its expert-coded
reference assignments. The fake provider replays cassette responses
deterministically; the golden test then computes Cohen's kappa between the
replayed coding output and the reference coding, enforcing the ≥ 0.75 target
against the pack's documented behavior.

When a real provider is available, `--llm-record <cassette.yml>` re-records a
cassette from live calls (excluded from CI; requires pack version bump per
builder instruction §5).

## Consequences

- CI is fully offline and deterministic.
- Golden tests verify pipeline + pack prompt mapping + scoring logic, not live
  model quality; live quality is a documented, user-side concern (kappa IRR
  reporting exists precisely for that).
