# ADR-002: Token budget via character heuristic

## Status

Accepted (2026-08-18)

## Context

TAD §6 / config `coding.batch_token_budget = 4000` requires a token estimate
when batching segments. No tokenizer is named anywhere in the specs, and the
exact tokenizer differs per provider (OpenAI vs Anthropic vs Ollama models).

## Options

1. **tiktoken.** Accurate for OpenAI models, an extra dependency, wrong for
   non-OpenAI models.
2. **Provider-specific tokenizers.** Accurate everywhere, heavy and complex.
3. **Character heuristic (`chars / 4`).** Rough but provider-neutral; used only
   for batch-size estimation, never for billing or reproducibility-critical
   values.

## Decision

Option 3: batches are cut when either `batch_size` segments or an estimated
~`batch_token_budget` tokens (estimated as total characters / 4) is reached.
The heuristic affects only how segments are grouped into prompts, not the
coding results themselves.

## Consequences

- No extra dependency; deterministic across machines (reproducible batching).
- Token estimates are approximate (±20%); budget exists as a guardrail.
